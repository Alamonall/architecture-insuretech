# Архитектурная оценка REST API

## Плюсы

- Простая и понятная иерархия
- Логичная структура: /clients/{id}/subresource
- Явное разделение доменных объектов

## Минусы

- Потенциальный overfetching / underfetching
- Чтобы получить клиента + документы + родственников → нужно 3 запроса
- Нет возможности гибко выбрать поля
- Жёсткая структура endpoint-ов
